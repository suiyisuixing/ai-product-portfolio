# HDFS + Spark · 四节点异构集群评论聚合与跨机耗时剖析

4 人课程小组项目（CSI205 · 2026.10 – 2026.11） · 我负责 Master 节点部署、跨机网络排障与技术报告主笔

## 1. 集群拓扑与资源配置

围绕大规模电商评论离线清洗与多维聚合任务，在 4 台异构宿主机（ARM64 / x86_64 桥接 Ubuntu 24.04）上部署 `1 Master + 3 Worker` 分布式计算环境：

| 组件 | 版本与关键配置 | 验收方式 |
| --- | --- | --- |
| **Hadoop HDFS** | `Hadoop 3.5.0` · `128 MiB` 分块大小 · 副本因子 `2` · DataNode 传输端口 `TCP 9866` | `hdfs fsck /` 块健康度与双副本分布核验 |
| **Apache Spark** | `Spark 3.5.9 Standalone` · `3 Executors`（单 Worker 各 `1` 核 / `2 GiB` 堆内存，合计 **`3` 核 / `6 GiB`**） · 固定 `spark.blockManager.port = 7337` | Master Web UI Executor 注册与 Stage 任务均衡分发检查 |
| **数据集规模** | Amazon Reviews 8 分片列式 Parquet：清洗后 **`4,624,615`** 条有效评论、**`137,249`** 件商品、`54` 个细分品类 | 单机 4 虚机与四物理机共 `6` 轮运行与独立基准 SQL 输出逐字节一致 |

## 2. 多表关联口径与业务分布统计

使用 PySpark / Spark SQL 读取 8 分片评论表并按 `parent_asin` 关联商品元数据表，统一清洗空值与缺失类目后产出两类核心结果：
1. **54 类目规模与集中度分布**：统计各类目的独立评论用户数、独立商品数与星级占比。实测识别头部两个核心类目贡献 **`62.94%`** 评论量，五星评价占 **`61.15%`**，并将 **`2.98%`** 缺失类目记录显式归入 `Unknown` 桶避免静默丢行。
2. **稳定次序消歧 Top-10 榜单**：统计并复核以评论数降序为主序、`parent_asin` 字典序为次序的确定性消歧榜单（榜首单品 **`18,105`** 条评价、均分 **`4.65`**），保证多节点并行重跑结果逐字节一致。

## 3. 跨机防火墙排障与单虚机 vs 四物理机耗时归因

联调初期出现 HDFS 写入副本超时与 Shuffle 拉取挂起，经排查定位为 Worker 节点入站 `UFW` 规则拦截了 DataNode 数据传输端口（`TCP 9866`）及固定配置的 Spark BlockManager 端口（`TCP 7337`）。显式固定端口并放行集群子网规则后恢复稳定运行。

随后在相同代码、相同 `3 Executors (3 cores / 6 GiB)` 资源配额下对比两种拓扑的分阶段中位耗时：

| 运行环境 | 节点间网络 RTT | 端到端中位耗时 | Stage 2（双 `COUNT(DISTINCT)` Shuffle 聚合） | 核心瓶颈归因 |
| --- | --- | ---: | ---: | --- |
| **单宿主机 4 虚拟机** | `0.36 – 0.59 ms` | **`11.22 s`** | `2.19 s` | 虚拟网桥内存态转发，网络延迟可忽略 |
| **4 台物理主机无线桥接** | `183 – 209 ms` | **`36.42 s`** | **`17.91 s`** | 同一 SQL 同时计算独立评论用户数与独立商品数两个 `COUNT(DISTINCT)`，触发 Spark `Expand` 算子将中间行膨胀至约 **`1,387` 万行**，跨高延迟共享无线热点 Shuffle 成为主导开销 |

在同门课程个人项目（`2026.09 – 2026.11`）中，另实现 `Hadoop 3.5.0 MapReduce Streaming`（Python Mapper / Combiner / Reducer）与 `PySpark 3.5.7 RDD` 批处理管道，在 `1x / 10x / 100x`（最高 `15.4 MB`）教学规模负载下执行 **`18` 轮**独立新进程测试：量化验证了小规模输入下框架进程与调度初始化开销远大于实际扫描计算耗时，同时对比了同一 SparkContext 内 `cache()` 内存驻留复用对二次迭代计算的加速收益。
